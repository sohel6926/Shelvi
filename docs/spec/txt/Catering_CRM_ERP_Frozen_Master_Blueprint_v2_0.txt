1. Core Business Hierarchy - FROZEN
The permanent business relationship is:
     Legal Entity / Company -> Brand -> Branch -> Kitchen -> Store / Warehouse
     Customer -> Booking -> Event -> Sub-Event -> Meal Session
     Menu -> Product / Dish -> Recipe / BOM -> Item / Ingredient
     Purchase / Inventory / Production -> Staff / Vendor / Vehicle / Equipment
     Billing / Collection -> Event P&L -> Financial Close
    Example
    A single Wedding Booking can contain Mehendi Dinner, Wedding Breakfast, Wedding Lunch, Reception Snacks and
    Reception Dinner. Each session can independently track guests, menu, production, inventory, outside items, staff, vehicles,
    equipment, live counts, expenses, revenue and profit.




2. Golden System Rules - FROZEN
     One backend and one central database.
     Web and Android use the same business logic and source data.
     Every business record has a unique ID.
     Every event-related cost links to Booking, Event and Session where applicable.
     General expenses use an approved Overhead Cost Centre.
     No direct stock editing; stock changes only through stock movements.
     No silent payment editing, recipe editing or financially closed event editing.
     Important changes require audit history; sensitive changes require approval.
     Backend calculates money, tax, balances and profit.
     UI cannot bypass permissions.
     Actual data never overwrites historical quotation or event snapshots.
